## 작업 기준

첨부 프롬프트북의 기준 커밋은 ab63125772dc01052cfed90f5b7de7f72205d4df입니다. 작업 시작 main은 50c346c7382af25428e497d0dc7cbe336b8b3b65이며, 이미 UI 리마스터와 확장 삽화 롤북이 반영되어 있었습니다. 기존 구현을 대조해 부족한 동작과 가독성을 보완했습니다.

첨부 PNG 네 장과 기존 WebP의 크기 및 그림 구성을 시각적으로 확인했습니다. 같은 그림의 기존 최적화 파일을 사용합니다. 새 그림으로 음표와 쉼표의 기호·틱·부채꼴 각도를 대체하지 않습니다.

## 검증 경계

규칙·저장·통합·롤북 검사는 Node의 테스트 러너로 실행했습니다. 12종 재료의 틱·각도, 30개 단계의 생성·해답, 독립 포장 검산, 같은 박자 다른 종류, 저장 이주와 손상 복구, 중복 보상, 기억시간 정지와 오래된 예약 동작을 검사합니다.

실제 Chromium은 HTTP 리소스 응답으로 로컬 정적 파일을 받아 마우스·키보드·브라우저 DOM을 사용합니다. 단순 모의 DOM 결과와 구분합니다. 320×568, 360×780, 390×844, 412×915, 768×1024, 1366×768, 844×390에서 화면·48px 조작·스크롤을 확인했습니다. 12종 선반, 200% CSS 확대, 이미지 로드 실패도 검사합니다.

물리 iPhone의 Safari, Android Chrome의 실제 오디오·주소창·safe-area·회전과 실제 학생 관찰은 미검증입니다. 브라우저의 모바일 흉내를 실기기 검증으로 표기하지 않습니다.

## 학생 관찰 시나리오

3~5명에게 처음 화면에서 “피자 주문 하나를 완성해 보세요”라고 안내합니다. 사용 전에 담는 방법이나 정답을 설명하지 않습니다. 첫 주문까지 누른 수, 첫 조각을 담기까지 걸린 시간, 듣기와 담기 혼동, 수량 이해, 되돌리기와 롤북 찾기를 기록합니다. 첫 연습 2회 이내 진입, 첫 재료 10초 이내, 도움 없는 완성 80%는 관찰 목표이며 달성 결과로 기록하지 않았습니다.
