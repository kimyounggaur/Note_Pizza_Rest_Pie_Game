- 버전: v1.0
- 작성일: 2026-11-16 (한국 시간)
- 대상: [Note_Pizza_Rest_Pie_Game](https://github.com/kimyounggaur/Note_Pizza_Rest_Pie_Game)
- 대상 코드 확인 기준: `ab63125772dc01052cfed90f5b7de7f72205d4df`
- 구조 참고: [Rhythm_Chord_Block](https://github.com/kimyounggaur/Rhythm_Chord_Block)

## 1. 이 문서의 사용법

1. 개발 도구에서 대상 저장소의 최신 상태와 작업 지침을 확인한다.
2. **M00 통합 시작 프롬프트**를 먼저 입력한다.
3. M01부터 M15까지 권장 순서로 진행한다. 각 단계의 검증이 통과하면 다음 단계로 이동한다.
4. 모든 단계에 이 문서의 공통 명세와 인수 기준이 적용된다. 단계별 프롬프트만 떼어 사용할 때도 공통 명세를 함께 전달한다.
5. 이미 구현된 부분은 최신 코드와 대조해 보완한다. 문서 작성 당시의 코드 줄 번호를 기계적으로 적용하지 않는다.
6. 구현·테스트·커밋·병합·운영 배포를 별개의 상태로 기록한다. 아직 수행하지 않은 작업을 완료했다고 보고하지 않는다.

### 권장 실행 순서

| 차수 | 실행 모듈 | 사용자에게 생기는 변화 |
|---|---|---|
| 기반 정리 | M00 → M01 | 현재 기능·데이터·위험을 확인하고 UI와 규칙을 분리할 기반 확보 |
| 1차 핵심 개편 | M02 → M03 → M04 → M05 → M06 | 빠른 시작, 큰 주문 카드, 탭으로 담기, 정확한 진행 표시 |
| 2차 학습 개편 | M07 → M08 → M09 | 연습·도전 분리, 행동형 튜토리얼, 쉬운 결과·복습 |
| 3차 화면 완성 | M10 → M11 → M12 → M13 | 반응형 배치, 에셋 정리, 접근성·소리·저장 안정성 |
| 마무리 | M14 → M15 | 전체 회귀 검사, 사용자 관찰, 검증된 배포 |

**이번 범위에 포함:** 화면 흐름, 정보 우선순위, 탭·드래그·키보드, 진행 표시, 연습/도전, 튜토리얼, 결과, 반응형, 저장 호환, 기존 롤북 연결, 기존 에셋 활용.

**별도 범위:** 회원가입·서버 DB·순위표·결제·기관별 관리자·새 악기·새로운 음악이론 게임. 이번 개편에 필요하지 않다.

## 2. 현재 상태와 바꿔야 하는 이유

### 2.1 현재 구현에서 확인한 것

| 지점 | 확인한 현재 동작 | 리마스터 방향 |

| `renderSplash`, `renderMain`, `renderMode`, `renderStage`, `renderOverlay` | 첫 플레이까지 스플래시, 메인, 주방, 지도, 미리보기, 튜토리얼을 통과 | 홈에서 시작 목적을 고르고 최소 단계로 첫 주문 진입 |

| `rulebook.js` | 전역 Game/NOTES/SCREEN/그리기 함수에 의존 | 구조 변경 시 명시적인 연결 어댑터로 통합 |

| `components/rhythm/Hud.tsx` | 짧고 일정한 상단 상태 표시 | 현재 손님·현재 주문·시간·일시정지 |

참고 게임에도 다른 장르에 맞는 밀집 정보와 회전 안내가 있다. 이를 모두 옮기지 않는다. 특히 예전에 수정한 PC 가로 화면 차단 문제를 재도입하지 않는다.

## 3. 최종 UX 공통 명세

### 3.1 첫 화면

- 독립된 ‘화면을 눌러 시작’ 관문을 없앤다. 초기 로딩 뒤 바로 홈을 보여 준다.
- 상단: 게임명, 소리 버튼, 도움말/설정 메뉴. 아이콘에는 읽을 수 있는 이름과 접근 가능한 label을 둔다.
- 중앙: 짧은 소개 ‘주문대로 조각을 담아 리듬 요리를 완성해요’와 큰 두 카드.
  - **연습하기**: ‘시간 걱정 없이 하나씩 배워요’.
  - **도전하기**: ‘주문을 맞추고 별을 모아요’.
- 첫 사용자의 ‘연습하기’는 피자 1단계의 쉬운 주문으로 곧바로 진입한다.
- 도전하기에서는 주방과 단계 선택을 하나의 선택 화면에 합친다. 주방 탭 + 단계 카드 목록으로 구성한다.
- 잠긴 주방과 단계에는 이유를 문장으로 보여 준다. 터치 반응 없이 조용히 무시하지 않는다.
- 도감·설정·롤북은 보조 메뉴에 둔다. 홈의 주요 선택과 같은 강조를 하지 않는다.
- 자동 재생 소리나 로그인 요구로 첫 진입을 막지 않는다.

### 3.2 이어하기의 정확한 의미

현행 코드에는 실제 진행 중 세션 저장이 없다. 이름만 ‘이어하기’로 붙이지 않는다.

- 유효한 세션 스냅숏이 있으면 **‘하던 요리 이어하기’**: 주방·단계·손님 번호와 저장 시각을 부제에 표시.
- 스냅숏은 없고 단계 진행만 있으면 **‘다음 단계 시작’**: 예를 들어 ‘피자 3단계’라고 표시.
- 완료·시간 초과·결과 전환 중인 스냅숏은 복구 후보에서 제외한다.
- 복구 직후에는 일시정지 상태이며 사용자가 ‘계속하기’를 눌러야 시간이 흐른다.
- 스냅숏 저장 실패 시 게임을 계속할 수 있어야 하고 ‘진행 저장을 사용할 수 없어요’라는 안내를 한 번만 표시한다.

### 3.3 플레이 화면의 네 구역

| 구역 | 구성 | 우선순위 |
|---|---|---|
| 상단 상태 | 뒤로/일시정지, ‘손님 1/3’, 시간 또는 ‘시간 제한 없음’, 도움 메뉴 | 짧게, 위치 일정 |
| 주문 카드 | 손님 작은 초상, 주문 재료 큰 기호·이름·박자·개수 | 무엇을 해야 하는지 가장 먼저 읽힘 |
| 중앙 접시 | 큰 접시, 담은 조각, 현재 접시 박자, 여러 접시 진행 | 가장 넓은 조작·피드백 영역 |
| 하단 조작 | 재료 카드, 되돌리기, 도움, 큰 서빙/주문 확인 버튼 | 엄지로 접근하기 쉬움 |

세로 화면은 위에서 아래로 읽는다. 넓은 화면은 왼쪽 주문, 중앙 접시, 오른쪽 재료·행동으로 배치할 수 있다. 한 번에 너무 많은 재료를 보여 글씨를 줄이지 않는다.

### 3.4 주문 카드의 표시 예

주문: 2분음표 1개 + 4분음표 2개.

| 재료 | 초기 | 일부 담았을 때 | 완료 |
|---|---|---|---|
| 2분음표 · 2박 | 0/1개 | 1/1개 | 체크 + ‘완료’ |
| 4분음표 · 1박 | 0/2개 | 1/2개 | 2/2개 + ‘완료’ |
| 주문 합계 | 0/4박 | 3/4박 | 4/4박 |

- 색만 바꾸지 말고 숫자·아이콘·문구를 함께 사용한다.
- 너무 많이 담은 종류는 `3/2개 · 1개 많아요`라고 표현한다. 표시를 2/2로 잘라 숨기지 않는다.
- 주문에 없는 재료는 별도의 ‘주문에 없는 조각’ 안내로 표시한다.
- ‘현재 접시 2/4박’과 ‘주문 전체 6/8박’을 구분한다.
- 모바일 주문 기호는 기본 32~40px, 본문은 기본 16px 이상을 목표로 한다. 패널을 축소해 글자를 11px로 만드는 방식은 사용하지 않는다.

### 3.5 입력 계약

| 입력 | 결과 |
|---|---|
| 재료 카드 탭/클릭 | 그 재료 1개를 접시에 담기 |
| 카드의 별도 ‘소리 듣기’ 버튼 | 소리·쉼표 안내만 재생, 담기지 않음 |
| 카드 드래그 후 접시에 놓기 | 그 재료 1개 담기 |
| 드래그 후 접시 밖에 놓기 | 추가 없음, 원래 위치로 복귀 |
| 카드에 키보드 포커스 후 Enter/Space | 1개 담기 |
| 되돌리기 | 마지막으로 담은 조각 1개 제거 |
| 서빙/주문 확인 | 현재 모드의 판정 흐름을 정확히 1회 실행 |

모든 추가 입력은 같은 command를 사용한다. pointerup과 click이 둘 다 발생해 2개 추가되는 일이 없어야 한다. 소리 버튼을 재료 버튼 안에 중첩하지 않는다. 카드 wrapper 안에 형제 button 두 개를 둔다.

### 3.6 연습·도전·러시

| 항목 | 연습 | 도전 | 러시 |
|---|---|---|---|
| 시간 | 제한 없음 | 기존 단계 제한시간 | 기존 러시 규칙 |
| 자동 도움 | 필요한 재료·개수 안내 | 사용자가 요청할 때 단계에 맞춰 도움 | 도전 규칙 기반 |
| 실수 | 원인과 고치는 행동을 표시 | 기존 판정·학습 카드 흐름 유지 | 기존 실패 종료 기준 유지 |
| 힌트 비용 | 무료 | 1~3단계 무료, 4단계부터 5코인 | 기존 단계 기반 비용을 명시 |
| 단계 별·코인·해금 | 지급하지 않음 | 기존 규칙 | 기존 기록/보상 |
| 저장 | 학습/튜토리얼 상태를 별도 저장 | 기존 진행에 반영 | 기존 최고 기록에 반영 |

연습 결과를 도전 기록에 섞지 않는다. 기존 `slowMode=true`를 유료 진행을 얻는 시간 무제한 도전으로 해석하지 않는다. 이전 설정은 마이그레이션 후 연습 모드 추천 안내로 연결하고 사용자가 모드를 선택하게 한다.

### 3.7 서빙 버튼의 의미

- 연습: 종류·개수·총량이 맞으면 **‘완성! 서빙하기’**. 그 전에는 필요한 행동을 구체적으로 안내한다.
- 도전·러시: 총 박자 조건이 맞으면 **‘주문 확인하기’** 활성화. 버튼 활성화가 정답 보증을 뜻하지 않도록 한다. 누르면 기존 `judge`를 통해 판정하고 서빙 결과를 보여 준다.
- 도전에서 요청하지 않은 정답을 자동으로 공개하거나, 정답만 담기도록 입력을 막지 않는다.
- 조각 수용이 불가능한 경우는 정확히 알린다: ‘접시에 1박 자리가 남았어요. 더 작은 조각을 골라 보세요’.

### 3.8 행동형 첫 튜토리얼

1. ‘4분음표를 눌러 보세요’ — 한 재료 카드만 강조.
2. ‘한 번 더 담아 2개를 만들어 보세요’ — 주문 숫자가 변하는 것을 보여 줌.
3. ‘주문이 완성됐어요. 서빙해 보세요’ — 큰 행동 버튼 강조.

튜토리얼은 시간 제한 없는 연습에서 진행한다. 건너뛰기·다시 보기·중단을 지원하며, 여러 화면 위에 길고 클릭을 막는 말풍선을 동시에 띄우지 않는다.

## 4. 변경하면 안 되는 음악·게임 불변식

| 재료 | 박자 | 내부 정수 틱 |
|---|---:|---:|
| 온음표 / 온쉼표 | 4 | 16 |
| 점2분음표 / 점2분쉼표 | 3 | 12 |
| 2분음표 / 2분쉼표 | 2 | 8 |
| 4분음표 / 4분쉼표 | 1 | 4 |
| 8분음표 / 8분쉼표 | 0.5 | 2 |
| 16분음표 / 16분쉼표 | 0.25 | 1 |

1. 1박=4틱, 접시 최대 4박=16틱=360°. 부동소수점 합산으로 판정하지 않는다.
2. 피자는 음표, 파이는 쉼표이다. 같아 보이는 크기라도 서로 다른 종류이다.
3. 주문 정답은 종류와 개수로 판단한다. 순서를 새 정답 조건으로 추가하지 않는다.
4. 주문 합계가 4박 미만일 수도 있다. 주문 전체를 매번 4박으로 강제하지 않는다.
5. 접시가 꽉 차고 주문이 남으면 다음 접시로 간다. 자동 접시 이동 규칙을 바꾸려면 별도의 명시적 변경으로 취급한다.
6. 기존 주방 해금: 파이는 피자 3단계 별 1개 이상, 믹스는 피자·파이 모든 10단계를 각각 별 1개 이상.
7. 기존 단계 해금은 직전 단계 별 1개 이상이다. 숫자 unlocked만으로 잠금을 해제하지 않는다.
8. 각 주방 10단계 클리어로 해당 러시 개방. 러시 첫 시간 24초, 주문당 0.5초 감소, 최소 8초.
9. 도전 별: 완벽 주문 비율 60% 이상 1개, 80% 이상+평균 남은 시간 20% 이상 2개, 100%+평균 남은 시간 35% 이상 3개.
10. 기존 코인·최고 기록·도감 수집을 보존한다. 연습으로 이 값을 올리지 않는다.
11. noteMark의 기둥·깃발·점 및 쉼표 모양, 조각 각도를 그림 에셋의 모양에 맞춰 왜곡하지 않는다.
12. 생성 주문이 실제 접시 규칙으로 완성 가능한지 확인한다. 예: 3박 조각 2개뿐인 주문은 첫 접시를 정확히 4박으로 채울 수 없어 현재 자동 이동 규칙으로 막힌다. 이런 주문은 생성 단계에서 배제한다.

## 5. 디자인·레이아웃·접근성 기준

### 5.1 정보 위계

- 강조색은 현재 해야 할 행동에 우선 배정한다.
- 배경과 손님은 접시·주문 정보보다 명도 대비와 움직임을 낮춘다.
- 박자와 개수는 텍스트로 읽히게 한다. 장식 이미지에 숫자를 구워 넣지 않는다.
- 한 버튼에 한 행동. 설정·도감·보상·주방 변경을 플레이 조작 옆에 모두 펼치지 않는다.
- 안내문은 1~2줄. 자세한 설명은 롤북에서 제공한다.

### 5.2 반응형 기준

| 화면 | 배치 |
|---|---|
| 폭 320~599px | 주문→접시→재료→행동의 1열, 재료가 많으면 일정한 높이의 스크롤 선반 |
| 폭 600~1023px | 가용 높이에 따라 1열 또는 접시+재료 2열 |
| 폭 1024px 이상 | 중앙 접시 중심의 2~3열, 주문·도움은 보조 패널 |
| 낮은 가로 화면 | 글자와 버튼 축소 대신 스크롤/압축 배치, 중요한 조작이 접근 가능 |

- 전체 게임을 CSS transform:scale로 줄이는 구조를 최종 제거한다.
- 헤더·행동 버튼·재료 선택은 최소 48×48 CSS px, 간격은 기본 8px.
- `100dvh`, safe-area, visualViewport를 고려하되 최소 높이와 실제 DOM을 기준으로 한다.
- 재료가 12종이면 버튼을 압축하지 않고 가로 스크롤 또는 그룹 탭(음표/쉼표)을 사용한다. 선택 상태와 스크롤 가능함을 드러낸다.
- 200% 확대에서는 읽기와 스크롤을 허용한다. 모든 내용을 무조건 한 화면에 우겨 넣지 않는다.
- PC·태블릿을 ‘세로로 돌리기’ 오버레이로 차단하지 않는다.

### 5.3 접근성과 안정성

- 포커스 표시, 논리적인 Tab 순서, Enter/Space 조작을 제공한다.
- 현재 값 변화는 단일 `aria-live=polite` 영역에서 요약한다. 매 프레임 남은 시간을 읽지 않는다.
- 모달에는 dialog 이름, 포커스 이동/순환, Escape 닫기, 닫은 뒤 원래 포커스 복귀.
- 글자 대비 일반 텍스트 4.5:1, 큰 글자 3:1을 목표로 실제 색 조합을 검사한다.
- 색 외에 모양·기호·문구로 음표/쉼표·완료/초과 상태를 구분한다.
- 움직임 줄이기 옵션을 존중하고, 성공 연출이 다음 버튼을 가리지 않게 한다.
- 클릭 지연, 과한 진동, 소리 중첩을 줄인다. 소리는 사용자의 입력 뒤 활성화한다.

## 6. 권장 코드 구조와 전환 원칙

현행은 index.html의 전역 함수에 규칙·입력·렌더·타이머가 섞여 있다. Next.js로 새로 만드는 것을 필수 조건으로 삼지 않는다. 기존 정적 배포를 유지하면서 분리할 수 있다.

이 폴더 구성을 반드시 그대로 만들 필요는 없다. 동일한 책임 분리와 검증 경계를 확보하면 된다.

**전환 주의:** 기존 rulebook.js는 Game/NOTES/SCREEN/noteMark 등의 전역에 의존한다. 게임만 ES Modules로 전환하고 기존 롤북을 그대로 두면 동작하지 않는다. 명시적인 API를 전달하는 초기화 방식으로 개편하고, 서로 다른 두 게임 상태나 두 이벤트 루프를 만들지 않는다.

### 6.1 상태 모델 예시

```js
{
  view: 'home',                 // home / select / game / result
  activity: 'practice',         // practice / challenge / rush
  phase: 'ready',               // ready / playing / paused / resolving / ended
  mode: 'pizza',                // pizza / pie / mix
  stage: 1,
  orderIndex: 0,
  currentOrder: { id, items, totalTicks },
  plates: [{ ticks, slices }],
  pauseReasons: [],             // user / help / tutorial / visibility
  tutorial: { version: 2, step: 0, active: false },
  clock: { remainingMs: 0, elapsedPlayingMs: 0 }
}
```

상태 이름은 조정할 수 있지만 화면, 놀이 종류, 진행 단계, 일시정지 이유를 한 개의 overlay 문자열로 겸용하지 않는다.

### 6.2 표시용 순수 계산 예시

```js
getOrderProgress(order, plates)
// -> {
//   items: [{ noteId, required, placed, remaining, excess, complete }],
//   unexpected: [{ noteId, placed }],
//   requiredTicks, placedTicks, remainingTicks,
//   activePlateTicks, activePlateRemainingTicks,
//   quantityReady, exactMatch
// }
```

- `quantityReady`: 주문 전체 틱 합계가 같음. 정답을 뜻하지 않는다.
- `exactMatch`: 필요한 종류·개수가 모두 일치하며 불필요한 조각이 없음.
- 데이터 변경 후 selector로 계산한다. 화면 카운터를 별도로 증가시켜 불일치를 만들지 않는다.

```text
러시에서는 주문 진행·최고 기록 계산에 필요한 상태도 보존하라.
진행 기록·보상 원장·세션 스냅숏은 일관된 하나의 저장 트랜잭션으로 갱신하라.
이미 보상한 주문을 오래된 스냅숏으로 복원해 다시 보상하지 말라.
합계 ticks·화면 진행률 등 파생값은 복구 시 재계산하라.
종류·단계·틱·용량·시간·세션 버전 및 통계/주문 인덱스의 일관성을 검증하라.
성공 연출/결과 전환 중 busy 상태를 복구하여 중복 보상을 만드는 일을 막아라.
복원 직후에는 일시정지로 시작하라.

pauseReasons 집합과 단일 게임 시계를 사용하라.
user+help 상태에서 롤북을 닫으면 user 일시정지가 남아야 한다.
visibility가 해제돼도 사용자가 누른 일시정지를 자동 해제하지 말라.
롤북 중 기존 setTimeout advanceOrder가 뒤에서 주문을 바꾸지 않게 전환 scheduler를 통합하라.
세션 교체 시 오래된 timeout 콜백을 취소하거나 토큰 검사로 무효화하라.
기억 주문의 안내시간도 일시정지 동안 흐르지 않도록 게임의 재생 경과시간을 사용하라.

검증:
- v1 fixture→v2 저장→재로드 후 기존 기록이 같다.
- 롤북+일시정지,튜토리얼+롤북,탭 숨김+일시정지 조합이 안전하다.
- 서빙 직후 다시 시작/홈 이동 후 오래된 콜백이 새 세션을 바꾸지 않는다.
- 새로고침 복원에서 코인·별·도감이 중복 지급되지 않는다.
```

## 9. 학습자 관찰 시나리오와 성공 목표

다음은 **출시 후 확인할 목표**이며, 현재 달성했다는 주장이 아니다.

1. 처음 보는 학생에게 ‘피자 주문 하나를 완성해 보세요’라고만 말한다.
2. 어떤 버튼을 먼저 누르는지, 드래그를 알아야 한다고 오해하는지 관찰한다.
3. 소리 듣기와 담기를 구분하는지 확인한다.
4. 주문서의1/2개를 보고 남은 개수를 말할 수 있는지 확인한다.
5. 잘못 담은 뒤 되돌리기를 찾는지 확인한다.
6. 롤북을 열고 원래 주문으로 돌아갈 수 있는지 확인한다.

권장 목표:

- 첫 연습 주문 진입까지2회 이내의 조작.
- 별도 설명 없이 첫 재료를 담는 데10초 이내를 목표로 관찰.
- 첫 주문을 도움 없이 완성하는 비율80% 이상을 목표로 개선.
- 의도치 않은 재료 이중 추가0건.
- 저장된 기존 성취 손실0건.
- 초과 조각/틀린 종류를 배경색만 보고 추측하지 않고 문구로 이해.

학생3~5명의 관찰은 작은 형성 평가다. 수치를 전체 이용자에 대한 통계적 검증으로 확대해석하지 않는다.

## 10. 개발 중 자주 발생할 실패와 교정 프롬프트

### 그림만 바뀌고 흐름은 그대로일 때

```text
현재 결과는 시각 스킨 변경에 머물러 있다.
첫 연습 진입 단계,탭으로 담기,주문별 수량 진행,모드별 서빙 의미를 실제 동작으로 완성하라.
새 UI의 사용 시나리오를 실행하고 이전 흐름과 비교한 증거를 제시하라.
```

### 탭과 드래그가 두 번 실행될 때

```text
재료 추가를 한 명령으로 통합하고 pointer gesture의 식별·완료·후속click 소비를 재설계하라.
전역350ms 클릭 금지 같은 임시 처방으로 정상적인 연속 입력을 잃지 말라.
탭1회/드래그1회/듣기/빠른 다른 재료 탭/키보드 혼합 시나리오를 검증하라.
```

### 롤북을 닫으면 일시정지가 풀릴 때

```text
롤북과 사용자 일시정지는 서로 다른 정지 이유다.
pauseReasons를 집합으로 처리하고 닫은 이유만 제거하라.
단일 overlay 문자열과 timer.running을 서로 독립적으로 덮어쓰는 경로를 정리하라.
예약된 다음 주문 전환도 같은 정지 규칙을 따르게 하라.
```

### 반응형에서 드래그 위치가 어긋날 때

```text
화면 배치만 바꾸고 고정된167,378 좌표와 scale 기반 gamePoint를 남겼는지 확인하라.

```

### 연습으로 도전 해금이 진행될 때

```text
보상과 진행 저장을 session.activity에 따라 명시적으로 분리하라.
연습 결과를 기존 finishStage/도전 별/코인 지급 경로로 보내지 말라.
연습 반복 후 기존 진행 객체가 바뀌지 않는 테스트를 추가하고 저장된 기존 기록을 보호하라.
```

### 일부 단계를 시작하면 멈출 때

```text
주문 생성의 중복 추첨 무한루프와 접시 포장 불가능 주문을 함께 검사하라.
재료1종,고정난수,3박×2개,최대3접시 주문을 포함해 유한 시간 종료와 해답 경로를 검증하라.
시도 상한을 넘으면 allowed 안의 검증된 주문을 반환하라.
```

## 11. 최종 완료 정의

다음 항목을 모두 확인하고 실제 미완료는 그대로 표시한다.

- [ ] 기존 드라이 브러시 에셋을 사용하면서 핵심 정보의 가독성을 확보했다.
- [ ] 첫 연습 주문까지2회 이내의 조작으로 진입한다.
- [ ] 탭·드래그·키보드가 같은 명령을 사용하고 중복 추가가 없다.
- [ ] 듣기는 담기와 독립된 행동이다.
- [ ] 재료별 개수·초과·불필요 조각과 전체 박자가 정확히 표시된다.
- [ ] 4박 미만 및 여러 접시 주문을 올바르게 처리한다.
- [ ] 연습·도전·러시의 시간과 보상이 구분된다.
- [ ] 세 단계 행동형 튜토리얼과 다시 보기 기능이 있다.
- [ ] 작은 모바일과PC에서 실제 글자·버튼 크기와 드롭 좌표가 맞는다.
- [ ] 12종 재료의 기호·틱·부채꼴 각도가 정확하다.
- [ ] 롤북·일시정지·탭 숨김이 서로 덮어쓰지 않는다.
- [ ] 기존v1 기록을 보존하며 저장/복원 실패가 게임을 막지 않는다.
- [ ] 검증된 세션만 실제로 이어하기한다.
- [ ] 예약 콜백과 서빙 중 연타가 중복 보상을 만들지 않는다.
- [ ] 실제 브라우저·실기기·목DOM 결과를 구분하여 보고했다.
- [ ] 승인된 범위에서 저장소/배포 상태를 확인하고 결과를 링크했다.
